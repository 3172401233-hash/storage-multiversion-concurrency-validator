# storage-multiversion-concurrency-validator
验证多版本对象并发读写、可见性和清理边界

## 说明

本仓库用 Python(兼容 3.8.2)校验对象存储开启多版本后的并发行为:
读请求、覆盖写、删除标记和后台清理可能同时发生,某个版本在一个副本
可见并不代表另一副本已经看到相同状态。

**所有状态均为本地事件模型。** 代码不连接任何真实对象存储,也不起
线程或网络;它把并发操作表示为按写入序号排序的本地事件,逐副本应用,
从而确定性地计算:

- 每次读取的可见版本(当前读或快照读);
- 并发操作后的最终目录状态(每个副本的版本集合、当前版本、清理水位)。

## 模型语义

- 输入:对象版本、ETag、写入序号、删除标记、读取条件(快照)、
  副本位置、清理水位。
- 当前读只能看到写入序号最大的非删除标记版本;删除标记和普通旧版本
  对当前读不可见。
- 条件写(`put_if`)必须绑定指定版本:协调副本当前版本与声明的基版本
  不一致时抛出 `ConditionalWriteFailed`。
- 重复删除幂等:当前版本已是删除标记时不再产生新版本。
- 后台清理(`cleanup`)只移除序号不超过水位、非当前版本、且未被任何
  活跃快照引用的版本。
- 事件可按副本子集应用,用于模拟多副本之间的可见性差异。

## 运行测试

```sh
python -m unittest
```

测试覆盖并发覆盖、重复删除、旧条件写、多副本差异,以及清理水位与
快照保护边界。

## 文件

- `multiversion.py` — 本地事件模型(版本、副本、快照、清理)
- `test_multiversion.py` — 单元测试
